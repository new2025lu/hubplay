# 架构说明

## 进程与数据流

```
┌─────────────── 主进程 src/main.js ───────────────┐
│  窗口 / 菜单 / 单实例锁 / 命令行开关 / 硬解策略    │
│  appRoot() = app.getAppPath()                    │
└───────────────┬──────────────────────────────────┘
                │ http://127.0.0.1:<port>（同源）
┌───────────────▼──────── src/server.js ───────────┐
│  静态托管 renderer/                              │
│  /p        流代理：改写播放列表、透传防盗链头      │
│  /api/*    导入 / 线路 / 嗅探 / 编码 / 测速 / 转码 │
│  prefetch.js  分片预取缓存（内存，只缓存分片）     │
└───────────────┬──────────────────────────────────┘
                │
      ┌─────────▼─────────┐        ┌──────────────────┐
      │ 上游 IPTV 源       │        │ 内置 ffmpeg       │
      │ (m3u8 / TS / FLV) │───────▶│ 转 H.264+AAC fMP4 │
      └───────────────────┘        └────────┬─────────┘
                                            │ 本地临时目录
┌─────────────── 渲染进程 renderer/app.js ───▼──────┐
│  引擎选择 hls.js / mpegts.js / flv.js / 原生       │
│  线路切换、看门狗、两级救援、诊断面板               │
└───────────────────────────────────────────────────┘
```

## 播放决策链

1. **容器嗅探** —— 读上游开头若干字节判断容器（`stream.detectContainer`），
   地址看不出扩展名的走 `/api/sniff`。
2. **编码预判** —— `/api/codec` 让 ffprobe 报出视频/音频编码，
   `codecVerdict()` 给出 `direct` / `remux` / `transcode` 三档结论。
3. **可用性预检** —— `/api/sniff?preflight=1` 在起播前确认「真正要播的那个分片」能取到。
   只探容器是不够的：存在一类源，播放列表能拿到且格式合法，但分片被源站拒绝。
4. **选线** —— 候选按「实测速度降序 → 能否直解 → 容器稳定度」排序。
5. **起播** —— 直解走对应引擎；判定转码则起 ffmpeg 会话，播放器读本地 HLS。

## 为什么转码档要单独做抖动治理

国内相当一部分源是**突发式交付**：播放列表里恒握着若干秒存量，但新分片按约 1 倍速发布。
于是任何「按实时节奏读源」的播放端都只能拿到刚好够播的量，缓冲长期贴底。
实测数据（某 MPEG-2 源，2026-10）：通道余量 9 倍以上、转码余量 1.8~4.4 倍，
瓶颈完全在「等源站发布」。因此采用三层措施：

| 措施 | 位置 | 作用 |
| --- | --- | --- |
| `-readrate` 预读三件套 | `src/local.js` | 起播冲刺读入存量；落后时倍速追赶 |
| 分片预取缓存 | `src/prefetch.js` | 分片提前进内存，ffmpeg 读本地而非等上游 |
| 目标延迟 / 缓冲上限 | `renderer/app.js` | 退让若干秒换抗抖动余量，上限放宽 |

## 看门狗与救援

| 看门狗 | 触发条件 | 动作 |
| --- | --- | --- |
| 起播兜底 | 起播超时 | 摆出真实状态，不假装还在努力 |
| 解码看门狗 | 有数据但不出帧 | 判定为解码问题而非网络问题 |
| 卡顿看门狗 | 时间轴不推进 / 前向缓冲见底 | 先 `startLoad()`，仍无效则 `recoverMediaError()` 重建 MediaSource |

> 注意：卡顿看门狗依赖 `state.activeAttempt`。转码档若不设置它，整条保护链会空转 ——
> 这是实际踩过的坑，转码路径必须显式挂上。

## 本地服务接口

| 接口 | 说明 |
| --- | --- |
| `GET /p?u=&r=&ua=` | 流代理；播放列表会被改写为经过本代理 |
| `POST /api/import` | 导入源地址，返回归一化频道表 |
| `GET /api/lines?id=` | 取某频道的线路列表 |
| `GET /api/sniff?u=&preflight=1` | 容器嗅探 +（可选）可用性预检 |
| `GET /api/codec?u=` | ffprobe 取编码 |
| `GET|POST /api/linespeed` | 线路测速 |
| `POST /api/remux` / `DELETE /api/remux?id=` | 起 / 停 ffmpeg 转码会话 |
| `GET /api/remux/status[?id=]` | 转码会话体检（started / 分片数 / seq / error / stderrTail） |
| `GET /api/prefetch` | 预取缓存快照 |
